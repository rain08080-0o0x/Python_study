# NPC対話プロトタイプ（モック版）

Python 3.12以降、外部パッケージは不要です。
生成AIのAPIは呼びません。接続箇所の代役と、出力の検証・状態管理を学びます。

## Windowsで実行する

このフォルダでターミナルを開きます。

```powershell
py -m venv .venv
.venv\Scripts\python.exe npc_game.py
.venv\Scripts\python.exe -m unittest -v
```

pyがなければ、環境で使えるpythonに読み替えます。
仮想環境の有効化は必須ではありません。上のコマンドで直接指定できます。
macOS / Linuxではpython3 -m venv .venv、.venv/bin/pythonを使います。

## 責務

|処理|担当|
|---|---|
|build_prompt|制約、ゲーム状態、プレイヤー入力の分離|
|mock_provider|外部AI接続の代役としてJSON文字列を返す|
|validate_reply|JSON、キー、型、長さ、許可行動の検証|
|ask_turn|外部呼び出しの失敗回復と、ゲームルールによる状態遷移|
|main|入力と表示|
|http_adapter.post_json|PC側のHTTP送信例。実サービス固有の契約は未実装|

## 実AIへ差し替える発展課題

1. 利用できるサービスの公式仕様と利用条件を調べる。
2. APIキーは環境変数で渡す。公開サイトや公開Gitには入れない。
3. provider(prompt)として関数を作る。サービスの要求形式へ変換し、応答から生成テキストを取り出してstrで返す。
4. ask_turn(message, state, provider)へ渡す。
5. 正常時、認証失敗、429、タイムアウト、不正JSONで確認する。

http_adapter.pyは汎用のPOST例です。そのまま特定の生成AIサービスには接続できません。
この教材は実際のAPIキーを必要とせず、実APIの接続試験を実施したものではありません。
同期通信をゲームのメインループで呼ぶと待ち時間中に止まります。非同期とUI待機の設計は講座19を参照してください。

## 自分で追加する

- 許可するactionを一つ増やし、必要なゲーム条件をコード側で定義する。
- 初回の挨拶と、ヒントを聞いた後の台詞を分ける。
- 不正応答のケースを追加する。
- 実APIをつないだら、応答時間と形式違反を記録する。

モック版を作ったことと、実際に生成AIを組み込んだことは区別して説明してください。
